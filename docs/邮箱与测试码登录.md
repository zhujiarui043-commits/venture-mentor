# 邮箱与测试码登录

## 登录与注册

登录页首先只显示「邮箱或测试码」输入框。输入完整邮箱后才显示密码栏，以及注册和找回入口；输入测试码则直接点击「进入工作空间」，无需密码。

邮箱账号注册需要昵称和 12–128 个字符的密码。注册时显示账号恢复码，保存后进入工作空间。当前不发送邮箱验证或找回邮件；忘记密码时，使用邮箱和保存的恢复码重设密码，随后保存新的恢复码。重设密码会撤销已有邮箱会话，原恢复码失效。

工作空间右上角的「退出登录」按钮返回登录页，可以切换邮箱账号或测试码。

## 项目数据

测试码仍对应原项目 ID `team-测试者标识`，原 Cookie 格式和 24 小时登录有效期继续兼容。未修改测试码配置时，原测试码和已保存的项目继续使用。

邮箱账号目前各自拥有独立项目；它与测试码的原项目不会自动合并。邮箱会话有效期 7 天，服务端保存会话令牌的 HMAC；密码带独立盐，使用 scrypt 存储。邮箱注册、登录和恢复请求具有持久限流。本次新增邮箱和测试码共用入口，基于当前恢复后的独立项目版本实现。

## 本地运行

```bash
pnpm run build
pnpm run db:migrate:local
pnpm run dev
```

每条命令成功后再执行下一条。全新的数据库需要按 `MACOS.md` 先创建原项目表，再执行账号迁移。

沿用 `.dev.vars` 中的 `SESSION_SECRET` 和 `TEST_ACCESS_CODES`。只用邮箱时，`TEST_ACCESS_CODES` 可以是 `{}`。AI 配置继续使用原密钥。

迁移文件 `drizzle/0001_dual_login.sql` 新增或保留邮箱账号表，并新增邮箱会话、限流表及索引；不删除、更新原项目记录。已存在兼容的 `users` 表时保留原账号。

## 线上测试站

邮箱账号表迁移及新版 Worker 已于 2026-10-12 部署到原测试站，版本为 `2e0e965a-2891-4ddd-95e1-51dc019a77b2`。原测试码和项目数据继续兼容；新用户可在同一登录页注册邮箱账号。

以后发布时，部署脚本会在构建和数据库 ID 核对后执行 `pnpm run db:migrate:remote`，再发布 Worker，并保留原远端密钥和测试码配置。邮箱密码哈希的 CPU 消耗仍应结合远端 Workers 套餐观察。
