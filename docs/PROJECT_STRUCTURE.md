# 文件组织说明

开发命令均在项目根目录执行。源码按现有职责分目录，保持引用和部署路径稳定。

| 目录 | 用途 |
| --- | --- |
| `app/` | 页面、全局样式及服务端 API |
| `components/`、`hooks/` | UI 组件及交互逻辑 |
| `lib/` | 导师工作流、账户、材料、分析和记录管理 |
| `knowledge/` | 应用实际读取的知识规则 |
| `db/`、`drizzle/` | 数据结构和迁移历史 |
| `public/`、`vendor/` | 字体、图标、第三方样式及许可证 |
| `scripts/` | 运行、安装、构建、字体处理和数据库辅助脚本 |
| `tests/` | 回归检查，`fixtures/` 存放材料样本 |
| `docs/` | 使用、运行和文件管理文档 |
| `config/` | 非敏感部署配置 |

框架配置、类型声明、包管理文件和部署入口保留根目录。`components.json` 用于 UI 组件生成；Linux 托管安装脚本、字体生成脚本和测试样本也有用途，不按日常使用频率删除。

`.dev.vars` 保存私有配置，`.wrangler/state/` 保存本地数据，均不提交 Git。`node_modules/` 保留已安装依赖；现有 `dist/` 保留本地预览及部署配置，避免影响运行。

本次清理只删除改名前遗留且进程已不存在的 `.vinext/dev/lock.json` 和空缓存目录。文档统一归入 `docs/`，业务源码、测试、静态资源和数据库未改动。
