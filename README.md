## 竞品搜索反馈与多文档附件

竞品搜索点击后会在页面显示检索状态，并打开导师面板。存在待确认建议时，入口显示“查看待确认建议”，点击即可处理；原有建议不会被覆盖。错误会在竞品页显示，可刷新项目状态后重试。Tavily 请求限时 20 秒，DeepSeek 每次整理请求限时 60 秒，避免一直等待而没有反馈。

“附材料”支持一次多选 XLSX / DOCX / DOC，也可追加 TXT / CSV / Markdown，最多同时附加 5 份。Excel 和 Word 文件上限 5 MB，每份提取内容上限 12000 字，所有附件正文合计最多 40000 字。文档独立解析，一份损坏不影响其他成功读取的附件；发送前可以逐份预览、移除。发送成功后每份材料各有编号和文件名，访谈原话及证据引用按实际文档核对。统计 CSV 或 Excel 时每轮只用一份数据表，避免把不同样本混为一张表。

部署后测试：先选择两份内容不同的 Word 并预览，发送“比较这两份访谈的共同点与差异”，在调研验证中核对两份原文和引用编号。竞品页点击“联网搜索并分析”应立即显示正在处理，或明确提示需要处理旧建议；失败时显示错误。

参考 [Coze 的工作流与对话流](https://docs.coze.cn/guides_workflow_and_chatflow)，现有导师将连续讨论、知识解答、成果任务和材料解读分别处理。明确请求生成画布、诊断、竞品分析、假设或访谈等任务时，可从任意页面发起，系统选择相应模块的知识规则，成果仍需用户确认才保存到对应模块。确认后页面打开该模块。

普通解释不强制生成成果，也不修改项目记录；创意补充继续使用增量确认。自动联网仍由模型按需调用，沿用每轮一次检索、可关闭联网和来源核对规则。回答可以附带最多三个后续请求，点击才执行；待确认建议未处理时不显示这些按钮。

当前任务路由识别明确的任务词与执行要求，模糊请求保留当前页面上下文；不支持一次请求并行生成多类成果。未连接 Coze 服务，不需新增账号或密钥，也不需要迁移数据库。生产部署方式和测试网址不变。

队友部署后可测试：

- 在商业画布页问“请解释商业画布是什么意思？”，应直接解释，不出现九格待确认成果。
- 在项目总览问“帮我生成商业画布”，应生成待确认的九格成果；确认保存后打开商业画布页。
- 在项目总览附上 CSV `阶段,人数` / `访问,100` / `报名,20`，问“分析这份测试数据漏斗”，应生成调研验证成果并显示 20% 转化率。
- 正常讨论创意时，旧字段不重复进入待确认；点击后续建议，应接续当前对话，已有记录保持原样。
- 问“现在有哪些类似产品？”时，可以自动联网并展示来源；关闭联网后，应说明没有实时核实。

## 知识库检索与项目记忆更新

Agent 根据当前页面和具体任务选择知识库章节，区分访谈、问卷设计与分析、MVP 设计与市场测试分析。项目字段分别保存来源、用户确认状态和现实依据状态；未提供的信息保持未知。新增购买者、付费者、购买决策者、问题发生频率和已付出成本作为按需补充字段。旧项目记录按原样读取，缺少来源标注时显示“旧记录来源待核”，不会自动变为已验证事实。

## 知识库成果结构更新

- **创意诊断（KB04）**：八维分别记录判断、来源、关联假设、局限、风险影响和下一步，并展示版本变化。雷达图依旧只表示当前能否形成阶段判断。
- **访谈与问卷（KB07、KB08）**：上传 TXT／Markdown 访谈材料后，可保留可回查的逐字摘录和材料编号；上传 XLSX 或 CSV 问卷后，程序计算原始行数、缺失值、各列频数，并可切换变量查看图表。Excel 多工作表文件默认选取数据量最大的非空工作表。不会自动剔除无效答卷或推断样本代表性。
- **MVP 与测试（KB09、KB14）**：MVP 任务卡记录关联假设、对象、步骤、指标分子分母、周期、阈值和停止条件。测试漏斗接受 XLSX 或 CSV，首行为 `阶段,人数`，其余行按同一批对象的实际路径排列，例如 `访问,100`、`报名,30`。只计算相邻阶段转化；口径、对象和观察周期仍需人工核对。
- **商业画布和竞品（KB10、KB11）**：九格画布可以查看来源、假设、状态、限制、下一步及版本变化；竞品比较保留用户材料摘录、日期和待核实状态。竞品洞察新增主动联网搜索入口，使用方法见下文。

每份材料正文最多 12000 字，最多 5 份材料合计 40000 字，超过时请分批上传。旧的文字分析仍可读取，新的结构化成果需要重新生成并确认。上述更新只修改项目 JSON 的内容结构，无需新增 D1 表或重置项目记录。

## 结构化结果、证据版本与长期记忆更新

- 请求生成八维诊断、九格画布或 MVP 任务卡时，若 DeepSeek 返回的必需结构缺失，系统会再请求一次。仍不完整则提示错误，本轮不写入对话、材料或待确认建议。普通解释性提问不强制生成成果。
- 访谈证据可在待确认卡片中查看原话、方向和目标假设版本。同轮实质修订假设时，指向当前版本的证据存入旧版历史，明确指向修订后版本的证据才进入新版；原材料仍须逐字核对。
- 对话除最近消息和成果外，还会按本轮问题选择较早的相关成果、用户原话和已附材料。历史材料保留原有来源与限制，不会自动视为验证通过。历史检索有长度上限，较长的材料可能只传入相关片段。

## 竞品选择与保留

在对话中明确说明某个竞品的某项信息已经核实（例如“Dovetail 的价格我已经核实过了，就是 99 元”），会自动更新当前对照表，即使原值相同也会更新状态。最近对话明确指向一个产品和字段时，“这一项已经核实过了”也可更新。程序直接保存可明确对应的核实声明，不依赖模型是否输出状态修改字段。对应字段显示“用户已核实”，详情保存核实原话、对应对话与记录时间，并清除该项已解决的旧待核实提示；未核实字段继续保持原状态。普通补充仍标为待核实，再次修改已核实的值时需要重新核实。原值只有未知且用户未提供具体内容时，会说明未更新的原因。用户核实记录、原网页来源和历史版本随项目保存，刷新后仍可查看。

竞品对照表的每一项都可勾选“保留”，选择会保存到当前项目，刷新页面后仍然有效。后续成功搜索仅替换未勾选项；已勾选项保留内容、来源链接、摘录和原检索日期，同名新结果不会重复加入或覆盖已保留项。取消勾选后，该项仍显示在当前对照表中，下一次搜索时才会被替换。历史分析记录继续保留各轮的原始结果。搜索失败不会改动选择。

运行 `npm run test:search` 验证连续搜索、去重、持久化、取消保留、编辑保留项与冲突处理；运行 `npm run test:retention-ui` 验证实际页面的勾选、刷新和手机操作（需要可用的 Playwright Chromium，也可通过 `PLAYWRIGHT_MODULE_PATH`、`PLAYWRIGHT_EXECUTABLE_PATH` 指定运行环境）。

## 普通对话自动联网

输入框下方的「自动联网（按需）」默认开启。模型通过 DeepSeek 的 `search_web` 工具调用判断是否需要实时依据，不限制在竞品页面，也不将技术问题强制变成竞品分析。可以直接问：

- 「现在有哪些能实现语音转文字的技术或 API？」
- 「市面上有没有与这个想法类似的产品？」
- 「这些工具目前的价格和免费额度是多少？」

询问一般概念、澄清创意、解释已上传材料时通常直接回答。关闭勾选，或在本轮明确说「不要联网」「只根据我上传的材料」，程序不开放自动搜索工具。每轮最多实际发起一次搜索，模型因引用缺失而重试时复用本轮结果。

联网回答下方显示检索时间、可点击的来源、摘录，以及本轮完整来源列表。引用编号只对应这轮结果，链接由服务端根据 Tavily 返回的 URL 填入。自动搜索回答缺少可从来源逐字核对的引用时，会再请求模型一次；仍缺失时本轮不保存。搜索不可用时，回答下方显示具体原因，并要求模型说明未能联网核实。正常纯问答直接保存为聊天，可继续提问；需要修改项目资料、生成成果或关联证据时才显示「待你确认」。

网页信息不会自动覆盖项目字段、名称或成为访谈证据。根据公开网页做出的建议仍需核对，价格和功能以对应产品官方说明为准。联网查询只应包含简短公开主题；完整材料用于 DeepSeek 分析，不作为 Tavily 的搜索请求正文。

## 上传 Word 和 Excel 材料

「附材料」支持 `.xlsx`、`.docx`、旧版二进制 `.doc`、TXT、CSV 和 Markdown。旧版 `.xls` 请先在 Excel 中另存为 `.xlsx`。Excel 和 Word 文件上限 5 MB，其他文本文件上限 1 MB；每份提取后的内容上限为 12000 字，超过时拒绝附加，不静默截断。大文件请删除无关列或拆分后分次上传。

选择 Word 或 Excel 文件后，服务器使用已登录会话提取内容，界面显示文件名、字数和「查看提取内容」。Excel 会保留单元格文本、数值、布尔值和常见日期，转为现有问卷分析可读取的表格文本；公式使用文件内已保存的计算结果。核对后再发送问题，提取内容与文件名随分析请求保存为项目材料；上传预览本身不写入项目记录，也不保存原始二进制文件。Word 的图片、扫描内容、页眉页脚、批注和页面版式不作为分析材料。加密、损坏或无可读内容的文件会提示原因。

访谈材料解读与访谈成果生成使用 8000 tokens 的输出额度；模型输出因长度被截断时，自动提高额度重试一次（最多 16000 tokens），同时要求精简重复说明并保留完整 JSON。文件大小与模型输出长度分别限制。分析失败时本轮材料和项目记录不保存，输入框中的附件与草稿保留，可直接重试；不会保存残缺的分析结果。

上传接口校验登录状态、文件格式、上传大小和 ZIP 解压大小，服务器只提取纯文本，不将文档转换为可执行网页。提取内容依旧作为用户材料供模型分析，其中的提示词或命令不能覆盖导师规则。

可运行 `pnpm.cmd run test:materials` 验证 Word 和 Excel 上传，或运行 `node tests/word-material.mjs`。测试覆盖表格 DOCX、旧版 DOC、XLSX 中文、数值、布尔值、日期、特殊字符、鉴权和解压限制，不使用生产数据库。普通自动联网、关闭联网、搜索失败、引用重试与纯问答连续发送包含在 `test:search` 中。

已配置好 Tavily 和 DeepSeek Secret 后，本次升级不需要重填密钥或迁移数据库。在项目目录运行 `deploy-and-smoke.cmd`，会执行原有逻辑、联网和 Word 测试，再保留现有 D1 ID 构建部署。

## 分析记录与访谈提纲导出

上传材料使用独立的 `M01、M02…` 编号，分析记录使用 `A01、A02…` 编号；`V1、V2…` 仍表示同类成果的版本，两类编号不共用计数。旧分析记录打开时会补充 A 编号，原材料编号、内部 ID 和证据引用保持原样，不需要迁移数据库。

明确生成、修改或优化访谈提纲时，完整内容须进入调研验证的待确认成果，并立即作为默认折叠的待确认分析记录显示；可展开核对完整正文并导出 Word，导出的草稿注明待确认。点击“确认保存”后才写入正式分析记录，保留旧版。继续调整已有提纲中的问题也按修订任务处理，优先参考当前待确认的完整版本。模型只返回聊天正文或空提纲时会要求补全，仍缺失则不写入记录。普通“提纲怎么优化”一类解释性提问继续直接回答。

待确认建议不会禁用聊天、上传材料或搜索。确认、修改和放弃入口固定显示在输入框上方；普通提问保留原建议，修改请求更新待确认草稿，未涉及的字段继续保留，项目资料仅在确认后更新。空白或已与记录一致的旧建议不再阻塞对话；多页面导致建议过期时自动重新读取项目状态。上传材料列表显示 `M04 · 文件名`，访谈分析记录的标题、Word 标题和文件名去掉误加的 M 编号前缀，来源引用中的材料编号继续保留。

各模块的分析记录默认只显示标题、版本、日期和两行预览，点击标题区域或“展开完整内容”查看全文，再点一次收起。原有历史记录也采用这套展示，不需要重新生成。竞品记录中的每个产品同样默认折叠，展开后按目标用户、任务、功能、价格、限制和来源展示文字卡片。

访谈提纲右下角的“导出 Word”可直接下载 `.docx`，折叠时也可使用。文件从完整已保存内容生成，包含提纲正文、限制、下一步和信息依据；支持中文、标题、项目符号和加粗，不会只导出两行预览，也不需要调用模型或消耗 API 额度。

竞品上方对照表保留“对象 / 类别”“用户与任务”“功能 / 价格”三列；任务、价格和限制各自成段，长英文按单词换行，窄屏在表格区域左右滑动。来源及核实状态集中在下方“分析记录与来源”的折叠卡片中，展开详情不会再重复表格。

运行 `pnpm.cmd run test:records` 检查默认折叠、Word 完整内容和格式、竞品非表格详情及来源保留。部署脚本已加入该检查。

Word 导出代码随页面加载，点击下载时无需再请求独立脚本，避免页面保持打开期间部署更新导致旧脚本失效。构建后启动本地服务，可运行 `pnpm run test:word-export-ui` 检查真实构建页面的桌面与手机完整 DOCX 下载，以及点击前阻断导出脚本请求时仍可下载。测试默认访问 `http://127.0.0.1:8787`，可用 `WORD_EXPORT_QA_URL` 指定已部署网址；所有项目 API 请求使用隔离的合成数据，不写入测试网站项目。浏览器依赖可用 `PLAYWRIGHT_MODULE_PATH`、`PLAYWRIGHT_EXECUTABLE_PATH` 指定，报告写入 `.qa-results/word-export-production/`。

## 调整导师对话面板

桌面端将光标移到导师面板左边框，会出现拖拽手柄；按住向左拖动扩大对话区域，向右拖动缩小。面板有最小与最大宽度，也会根据当前工作区宽度限制拖动范围。手柄可用 Tab 聚焦，再用左右方向键调宽，Home / End 到达当前最小 / 最大宽度。

右上角的全屏按钮可让对话占满浏览器页面；再次点击按钮或按 Esc 恢复之前的布局和宽度。切换时保留未发送草稿、已附材料和聊天历史。手机端保留全屏按钮，使用适应屏幕的宽度。运行 `pnpm.cmd run test:panel` 检查面板控件与宽度边界；实际桌面和手机交互另经浏览器验收。

## 深色模式

工作区右上角、登录页及全屏对话右上角都可切换深色 / 浅色模式。首次访问跟随系统外观；手动选择后保存在当前浏览器，刷新仍保留。项目、聊天、访谈卡片、竞品表格、来源、输入框和图表均采用相应配色，主题切换不会修改项目记录。

## 文件整理

当前代码保留实际引用的 9 个基础 UI 组件，以及应用、知识规则、数据库迁移、测试和部署脚本。删除未引用的模板组件、默认图标和旧缓存，并移除对应未使用依赖。`tests/fixtures/legacy-word.doc` 是旧版 Word 上传的回归样本，需保留；知识库原文和比赛文件仍在上一级工作区的 `资料/` 目录。

调研验证的分析记录按方式独立编号：用户访谈 A01 起、问卷调查 Q01 起、MVP 测试 T01 起。访谈补充提纲即使在下一步提到 MVP，也归入用户访谈。历史记录读取时同步迁移编号和结构化来源引用，记录 UUID 与原文保持不变。通用或待分类分析记录使用独立的 U 编号；上传材料仍使用 M 编号。

「假设与证据」对话中的「生成本页建议」会发送「更新当前假设与证据状态」请求。优先逐条复核已有假设的高／中／低处理优先级、依据与下一步；有可读取的访谈原文时，先校验证据判断，再据此决定处理顺序。没有新依据时说明保留原因，没有原文时保持证据判断并指出缺口。只有清单未覆盖关键问题时才新增假设。成功后自动保存，假设表述和版本保持原样，优先级变化及原因可在「查看证据与历史」回查。运行 `npm run test:interview-hypotheses` 验证批量更新、必要时新增、漏项与重复保护、失败不保存及刷新恢复；追加 `-- --browser` 可检查实际快捷入口。
