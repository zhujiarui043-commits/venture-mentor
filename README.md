## 联网竞品结构化失败修复

已有竞品比较的修改采用专用增量流程，带入完整竞品表、逐项引用和原搜索快照，模型只输出需要修改的对象与字段；可选字段为 `null`、缺少无关成果或返回精简修改 JSON 不再触发通用结构化错误。支持调整类别、修改差异说明、删除或添加候选，以及修改记录标题、限制和下一步；确认后保存为新版本，旧版和未涉及的产品、价格、引用保持原样。

普通措辞调整不重复联网，每次整理限时 25 秒，格式问题最多修正一次。明确要求联网或核对最新竞品、价格时，仍会重新搜索；关闭联网时沿用已保存资料。用户直接提供的事实更正可记录为“用户补充，待核实”，对应旧字段的引用会移除；不能用旧定价页的摘录给未经核实的新价格背书。格式或对象序号仍不正确时显示具体修改失败原因，本轮不改动原记录。

手动“联网搜索并分析”采用专用竞品整理流程，不再要求模型同时输出项目字段、画布、访谈、假设等无关结构。仅生成最多 3 个候选产品，价格和功能继续逐项核对本轮网页摘录；可选字段为空或 `null` 不会让整份搜索结果失败。

每次竞品整理限时 25 秒，格式问题最多修正一次，修正不重复 Tavily 搜索。网络错误或超时直接展示已检索的网页；两次格式校验仍不通过时也会保留来源，明确标记“自动竞品比较未完成”。此时只提供原始网页，不生成产品、价格或市场结论，确认后仅保存网页资料。普通对话、访谈、画布和诊断继续使用原有校验，Tavily 本身失败时仍报错且不修改记录。

## 竞品搜索反馈与多文档附件

竞品搜索点击后会在页面显示检索状态，并打开导师面板。存在待确认建议时，入口显示“查看待确认建议”，点击即可处理；原有建议不会被覆盖。错误会在竞品页显示，可刷新项目状态后重试。Tavily 请求限时 20 秒，DeepSeek 每次整理请求限时 60 秒，避免一直等待而没有反馈。

“附材料”支持一次多选 DOCX / DOC，也可追加 TXT / CSV / Markdown，最多同时附加 5 份。每份 Word 上限 5 MB、正文 12000 字，所有附件正文合计最多 40000 字。文档独立解析，一份损坏不影响其他成功读取的附件；发送前可以逐份预览、移除。发送成功后每份材料各有编号和文件名，访谈原话及证据引用按实际文档核对。统计 CSV 时每轮只用一份数据表，避免把不同样本混为一张表。

部署后测试：先选择两份内容不同的 Word 并预览，发送“比较这两份访谈的共同点与差异”，在调研验证中核对两份原文和引用编号。竞品页点击“联网搜索并分析”应立即显示正在处理，或明确提示需要处理旧建议；失败时显示错误。

## 对话与任务流程改进

参考 [Coze 的工作流与对话流](https://docs.coze.cn/guides_workflow_and_chatflow)，现有导师将连续讨论、知识解答、成果任务和材料解读分别处理。明确请求生成画布、诊断、竞品分析、假设或访谈等任务时，可从任意页面发起，系统选择相应模块的知识规则，成果仍需用户确认才保存到对应模块。确认后页面打开该模块。

普通解释不强制生成成果，也不修改项目记录；创意补充继续使用增量确认。自动联网仍由模型按需调用，沿用每轮一次检索、可关闭联网和来源核对规则。回答可以附带最多三个后续请求，点击才执行；待确认建议未处理时不显示这些按钮。

当前任务路由识别明确的任务词与执行要求，模糊请求保留当前页面上下文；不支持一次请求并行生成多类成果。未连接 Coze 服务，不需新增账号或密钥，也不需要迁移数据库。生产部署方式和测试网址不变。

队友部署后可测试：

- 在商业画布页问“请解释商业画布是什么意思？”，应直接解释，不出现九格待确认成果。
- 在项目总览问“帮我生成商业画布”，应生成待确认的九格成果；确认保存后打开商业画布页。
- 在项目总览附上 CSV `阶段,人数` / `访问,100` / `报名,20`，问“分析这份测试数据漏斗”，应生成调研验证成果并显示 20% 转化率。
- 正常讨论创意时，旧字段不重复进入待确认；点击后续建议，应接续当前对话，已有记录保持原样。
- 问“现在有哪些类似产品？”时，可以自动联网并展示来源；关闭联网后，应说明没有实时核实。

这个包把现有 AI 创业导师项目部署到你自己的 Cloudflare Workers `*.workers.dev` 地址；无需购买服务器。每位测试者使用独立测试码与独立项目记录，DeepSeek API Key 只设置在 Cloudflare Worker 的 Secret 中。原来本地项目和 `chatgpt.site` 的数据不会自动迁移到新的 D1 数据库。

## 准备

- Windows PowerShell、Node.js 22.13 或更高版本、pnpm 11.25.0。
- 你自己的 Cloudflare 账号，以及已开通的 Workers、D1 和 `workers.dev` 子域名。
- 你的 DeepSeek API Key。不要把 Key 发给测试者，也不要放进网站源码或聊天。

解压本文件夹，在文件夹空白处打开 PowerShell，然后逐行运行。这里统一使用 `pnpm.cmd`，可避开 PowerShell 对 `pnpm.ps1` 的脚本执行限制；无需调整系统执行策略：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd exec wrangler login
pnpm.cmd exec wrangler d1 create venture-mentor-team-test
```

第三条命令会输出 `database_id`（一串 UUID）。复制这个 UUID，然后在**同一个 PowerShell 窗口**运行下面命令，替换引号中的提示文字：

```powershell
$env:APP_D1_DATABASE_ID = '这里粘贴你刚创建的 database_id'
pnpm.cmd run build
pnpm.cmd exec wrangler d1 execute venture-mentor-team-test --remote --config dist/server/wrangler.json --file drizzle/0000_motionless_firebird.sql
pnpm.cmd exec wrangler deploy --config dist/server/wrangler.json
```

如 D1 远程 SQL 命令问是否确认，选择 `y`。看到部署 URL 后先不要邀请测试者，继续设置三项 Secret：

```powershell
pnpm.cmd exec wrangler secret put DEEPSEEK_API_KEY --config dist/server/wrangler.json
pnpm.cmd exec wrangler secret put SESSION_SECRET --config dist/server/wrangler.json
pnpm.cmd exec wrangler secret put TEST_ACCESS_CODES --config dist/server/wrangler.json
```

每条命令会提示输入值（输入时可能不显示字符）：

1. `DEEPSEEK_API_KEY`：粘贴你已有的 DeepSeek Key。
2. `SESSION_SECRET`：先在 PowerShell 中运行 `-join (1..2 | ForEach-Object { [guid]::NewGuid().ToString('N') })` 生成随机字符串，再粘贴结果。不要粘贴上面示例里的任何固定字符串。
3. `TEST_ACCESS_CODES`：粘贴一行 JSON，例如 `{"owner":"给自己生成至少16位随机码","tester1":"给队友甲生成至少16位随机码","tester2":"给队友乙生成至少16位随机码"}`。把中文示例换成各不相同的随机码。可以在 PowerShell 分别运行上述生成随机字符串的命令三次，然后填入 JSON 的三个值。三个名字 `owner`、`tester1`、`tester2` 保持不变，作为各自数据的标识。

部署成功后，Wrangler 会显示网址（通常是 `https://venture-mentor-team-test.<你的子域名>.workers.dev`）。你把网址和对应测试码分别发给两名队友即可。她们无需安装软件或填写 DeepSeek Key。请先用队友设备打开网址，确认 `workers.dev` 在她们网络中能访问；此前的 `chatgpt.site` 被拦截，并不能推断这个新网址一定可访问。

如果要更新团队测试版的代码（例如修复对话记忆），在已部署过的项目文件夹打开 PowerShell。先从现有构建结果读取真实 D1 数据库 ID，再构建和部署；不要用占位 ID：

## 限制

这个部署包是三人功能测试版：每人一份独立项目，登录 24 小时后需要再次输入测试码。测试码一旦泄露，知道它的人可进入对应测试者的工作区，必要时更新 `TEST_ACCESS_CODES` Secret 和 `SESSION_SECRET` Secret。Cloudflare 和 DeepSeek 的免费额度、账单和区域可达性以你自己的账号实际情况为准。

## 知识库检索与项目记忆更新

Agent 根据当前页面和具体任务选择知识库章节，区分访谈、问卷设计与分析、MVP 设计与市场测试分析。项目字段分别保存来源、用户确认状态和现实依据状态；未提供的信息保持未知。新增购买者、付费者、购买决策者、问题发生频率和已付出成本作为按需补充字段。旧项目记录按原样读取，缺少来源标注时显示“旧记录来源待核”，不会自动变为已验证事实。

假设证据新增原话、材料编号、材料位置、支持／反向／边界方向和所属假设版本。用户确认实质修订时，旧版的阶段与证据存入历史，新版重新开始记录证据；确认只是措辞调整时保留原版本与证据，另存编辑历史。旧证据字符串保留并标记来源与版本待核。以上记录改动存于现有项目 JSON，无需重新建表。当前 Agent 不会仅凭上传材料自动宣布假设已得到支持。

## 知识库成果结构更新

- **创意诊断（KB04）**：八维分别记录判断、来源、关联假设、局限、风险影响和下一步，并展示版本变化。雷达图依旧只表示当前能否形成阶段判断。
- **访谈与问卷（KB07、KB08）**：上传 TXT／Markdown 访谈材料后，可保留可回查的逐字摘录和材料编号；上传 CSV 问卷后，程序计算原始行数、缺失值、各列频数，并可切换变量查看图表。不会自动剔除无效答卷或推断样本代表性。
- **MVP 与测试（KB09、KB14）**：MVP 任务卡记录关联假设、对象、步骤、指标分子分母、周期、阈值和停止条件。测试漏斗接受 CSV，首行为 `阶段,人数`，其余行按同一批对象的实际路径排列，例如 `访问,100`、`报名,30`。只计算相邻阶段转化；口径、对象和观察周期仍需人工核对。
- **商业画布和竞品（KB10、KB11）**：九格画布可以查看来源、假设、状态、限制、下一步及版本变化；竞品比较保留用户材料摘录、日期和待核实状态。竞品洞察新增主动联网搜索入口，使用方法见下文。

每份材料正文最多 12000 字，最多 5 份材料合计 40000 字，超过时请分批上传。旧的文字分析仍可读取，新的结构化成果需要重新生成并确认。上述更新只修改项目 JSON 的内容结构，无需新增 D1 表或重置项目记录。

## 结构化结果、证据版本与长期记忆更新

- 请求生成八维诊断、九格画布或 MVP 任务卡时，若 DeepSeek 返回的必需结构缺失，系统会再请求一次。仍不完整则提示错误，本轮不写入对话、材料或待确认建议。普通解释性提问不强制生成成果。
- 访谈证据可在待确认卡片中查看原话、方向和目标假设版本。同轮实质修订假设时，指向当前版本的证据存入旧版历史，明确指向修订后版本的证据才进入新版；原材料仍须逐字核对。
- 对话除最近消息和成果外，还会按本轮问题选择较早的相关成果、用户原话和已附材料。历史材料保留原有来源与限制，不会自动视为验证通过。历史检索有长度上限，较长的材料可能只传入相关片段。

本地逻辑检查可运行 `pnpm.cmd run test:logic`（Windows PowerShell），不需要部署。代码沿用原有项目 JSON 数据结构，旧记录可以继续读取，无需建新表。本轮尚未在真实 DeepSeek 响应或线上页面中验收。

### 来源与验收

- 每次点击发起一次 `advanced` 搜索，最多保留 6 条有文本的网页，搜索请求只传项目方向与简短的当前请求，不传完整聊天或上传材料。根据 [Tavily Search 官方文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)，`advanced` 搜索通常消耗 2 个 API credits；账号计费以 Tavily 后台为准。
- 保留本轮搜索词、网页 URL、返回的摘录和检索时间。网页发布日期由 Tavily 提供，缺失时显示未提供，不用检索日期代替发布日期。
- 竞品名称需在来源中出现；功能、价格、目标用户、任务和限制需要逐字匹配的对应引用，否则显示「待核实」。匹配引用不等于已经独立核实网页事实，结果始终标记「网页资料待核」。网页来源不能覆盖项目字段、名称或自动成为访谈证据。
- 缺少密钥、额度用尽、限流、超时和无结果会显示具体错误。搜索失败或模型两次未生成比较结构时，本轮不保存聊天、材料或待确认建议。
- 搜索资料随现有项目 JSON 保存，旧竞品记录继续读取，无需新增 D1 表。

运行 `pnpm.cmd run test:search` 检查联网功能，或运行 `node tests/competitor-search.mjs`。测试使用模拟 Tavily／DeepSeek 响应，不消耗 API 额度。真实验收时，填写搜索词，确认出现可点击来源和比较表，保存后刷新页面检查记录仍在；再换另一个测试码检查数据隔离。

- 「现在有哪些能实现语音转文字的技术或 API？」
- 「市面上有没有与这个想法类似的产品？」
- 「这些工具目前的价格和免费额度是多少？」

询问一般概念、澄清创意、解释已上传材料时通常直接回答。关闭勾选，或在本轮明确说「不要联网」「只根据我上传的材料」，程序不开放自动搜索工具。每轮最多实际发起一次搜索，模型因引用缺失而重试时复用本轮结果。

联网回答下方显示检索时间、可点击的来源、摘录，以及本轮完整来源列表。引用编号只对应这轮结果，链接由服务端根据 Tavily 返回的 URL 填入。自动搜索回答缺少可从来源逐字核对的引用时，会再请求模型一次；仍缺失时本轮不保存。搜索不可用时，回答下方显示具体原因，并要求模型说明未能联网核实。正常纯问答直接保存为聊天，可继续提问；需要修改项目资料、生成成果或关联证据时才显示「待你确认」。

网页信息不会自动覆盖项目字段、名称或成为访谈证据。根据公开网页做出的建议仍需核对，价格和功能以对应产品官方说明为准。联网查询只应包含简短公开主题；完整材料用于 DeepSeek 分析，不作为 Tavily 的搜索请求正文。

## 上传 Word 材料

「附材料」支持 `.docx`、旧版二进制 `.doc`、TXT、CSV 和 Markdown。Word 文件上限 5 MB，其他文本文件上限 1 MB；每份提取后的正文上限为 12000 字，超过时拒绝附加，不静默截断。大文档请拆分后分次上传。

选择 Word 文件后，服务器使用已登录会话提取正文，界面显示文件名、字数和「查看提取内容」。核对后再发送问题，正文与文件名随分析请求保存为项目材料；上传预览本身不写入项目记录，也不保存原始 Word 二进制文件。段落、表格中的文本可读取；图片、扫描内容、页眉页脚、批注和页面版式不作为分析材料。加密、损坏或无可读正文的文档会提示原因。

上传接口校验登录状态、文件格式、上传大小和 DOCX 解压大小，服务器只提取纯文本，不将文档转换为可执行网页。Word 正文依旧作为用户材料供模型分析，其中的提示词或命令不能覆盖导师规则。

可运行 `pnpm.cmd run test:materials` 验证 Word 上传，或运行 `node tests/word-material.mjs`。已在本地 Cloudflare Workers 运行环境中验收表格 DOCX 与旧版 DOC 的实际上传和鉴权，不使用生产数据库。普通自动联网、关闭联网、搜索失败、引用重试与纯问答连续发送包含在 `test:search` 中。

已配置好 Tavily 和 DeepSeek Secret 后，本次升级不需要重填密钥或迁移数据库。在项目目录运行 `deploy-and-smoke.cmd`，会执行原有逻辑、联网和 Word 测试，再保留现有 D1 ID 构建部署。

## 分析记录与访谈提纲导出

上传材料使用独立的 `M01、M02…` 编号，分析记录使用 `A01、A02…` 编号；`V1、V2…` 仍表示同类成果的版本，两类编号不共用计数。旧分析记录打开时会补充 A 编号，原材料编号、内部 ID 和证据引用保持原样，不需要迁移数据库。

明确生成、修改或优化访谈提纲时，完整内容须进入调研验证的待确认成果；点击“确认保存”后，新版作为默认折叠的分析记录显示，保留旧版和 Word 导出。继续调整已有提纲中的问题也按修订任务处理。模型只返回聊天正文或空提纲时会要求补全，仍缺失则不写入记录。普通“提纲怎么优化”一类解释性提问继续直接回答。

各模块的分析记录默认只显示标题、版本、日期和两行预览，点击标题区域或“展开完整内容”查看全文，再点一次收起。原有历史记录也采用这套展示，不需要重新生成。竞品记录中的每个产品同样默认折叠，展开后按目标用户、任务、功能、价格、限制和来源展示文字卡片。

访谈提纲右下角的“导出 Word”可直接下载 `.docx`，折叠时也可使用。文件从完整已保存内容生成，包含提纲正文、限制、下一步和信息依据；支持中文、标题、项目符号和加粗，不会只导出两行预览，也不需要调用模型或消耗 API 额度。

竞品上方对照表保留“对象 / 类别”“用户与任务”“功能 / 价格”三列；任务、价格和限制各自成段，长英文按单词换行，窄屏在表格区域左右滑动。来源及核实状态集中在下方“分析记录与来源”的折叠卡片中，展开详情不会再重复表格。

运行 `pnpm.cmd run test:records` 检查默认折叠、Word 完整内容和格式、竞品非表格详情及来源保留。部署脚本已加入该检查。

## 调整导师对话面板

桌面端将光标移到导师面板左边框，会出现拖拽手柄；按住向左拖动扩大对话区域，向右拖动缩小。面板有最小与最大宽度，也会根据当前工作区宽度限制拖动范围。手柄可用 Tab 聚焦，再用左右方向键调宽，Home / End 到达当前最小 / 最大宽度。

右上角的全屏按钮可让对话占满浏览器页面；再次点击按钮或按 Esc 恢复之前的布局和宽度。切换时保留未发送草稿、已附材料和聊天历史。手机端保留全屏按钮，使用适应屏幕的宽度。运行 `pnpm.cmd run test:panel` 检查面板控件与宽度边界；实际桌面和手机交互另经浏览器验收。

## 深色模式

工作区右上角、登录页及全屏对话右上角都可切换深色 / 浅色模式。首次访问跟随系统外观；手动选择后保存在当前浏览器，刷新仍保留。项目、聊天、访谈卡片、竞品表格、来源、输入框和图表均采用相应配色，主题切换不会修改项目记录。
